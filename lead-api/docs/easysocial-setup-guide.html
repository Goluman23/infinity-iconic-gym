01How it works

Two jobs · one server

EasySocial stays the WhatsApp inbox, the record of every lead and the team's hand-over desk. The Infinity server does the thinking: who to message, which first message, and what to reply to anything a person types.

Broadcast CSV (camp, walk-in register, lapsed)

Save lead data + tags

Lead replies

Template button → booking chatflow
Typed text → brain node → reply

Every typed message
Lead types anything→Webhook node · /api/es/brain→Reply sent + lead fields saved→If inf_handoff → Human Handover·If inf_flow → switch to Booking / Plan match·If inf_has_buttons → buttons node→wait for next message ↺
The brain remembers where the chat is through lead fields (inf_ctx, inf_lang, inf_miss, inf_rep), so "1", "yes", "no" and "hi" mid-chat do the right thing. Two unclear messages in a row, or the same message three times, go to a person.

06Deploy

Vercel · 15 minutes
1
Vercel → Add New → Project → upload/import the infinity-lead-api folder. No build step.
2
Settings → Environment Variables: copy every line from .env.example. Keep DRY_RUN=1 and PROVIDER=easysocial. Make INTAKE_KEY and ES_BRAIN_KEY long random strings (two different ones).
3
Open https://<project>.vercel.app/api/health. Fix until es_token_set: true, first_touch_missing: [], es_tag_ids_missing: [], es_invalid_json: [] and season_today is right.
4
Open https://<project>.vercel.app/, enter the intake key, send one lead with your own number. In dry run you'll see every EasySocial call it would make. Then set DRY_RUN=0, redeploy, send again — the template should land on your phone.

07Chatbot

Chatbot → new chatflow "Infinity Brain"

One chatflow answers every typed message. Set it as the default / fallback chatflow for the WhatsApp number so nothing falls through, and keep your template-button keywords pointing at the booking chatflows.

B1

Webhook (n8n) node — the brain

GET https://<project>.vercel.app/api/es/brain?key=ES_BRAIN_KEY&leadId=[leadId]&message=[n8n_input_message]&phone=[phone]&name=[name] &ctx=[inf_ctx]&lang=[inf_lang]&miss=[inf_miss]&rep=[inf_rep]&last=[inf_last_msg]&stage=[inf_stage]
Response: {"message": "…", "lead_attributes": {…}, "last_response": "…"} — EasySocial sends message and saves lead_attributes on the lead. If the node can't fill lead fields in the URL, keep only leadId, message and phone: the server then reads the lead's fields itself.
B2

If / Else — in this order

inf_handoff is not empty→Human Handover (08)
inf_flow = booking→Switch chatflow → Booking
inf_flow = plan_match→Switch chatflow → Plan match
inf_has_buttons = yes→B3 buttons
else→wait for reply → back to B1
B3

API Interactive Button node

GET https://<project>.vercel.app/api/es/buttons?key=ES_BRAIN_KEY&ctx=[inf_ctx]&lang=[inf_lang]&name=[name]
Returns up to 3 reply buttons (titles ≤ 20 characters) for the answer the brain just gave. Every tap or typed reply goes back to B1 — the brain knows each button title, in English and Hinglish. For the full menu use the API Interactive List node with /api/es/list?key=…&lang=[inf_lang] (10 rows, last one switches language).
Simpler option: if the button node can't read [inf_ctx], add &numbered=1 to the B1 URL and skip B3. The options then arrive inside the reply as 1 · Call me now / 2 · Call me later / 3 · Quick answers, and the brain understands "1", "2", "3" or plain words.

09Booking & plan match

Keep these from the Flow Simulator

Booking chatflow

  • Morning / Evening / Weekend → 3 slots → confirm.
  • On confirm set inf_stage = st_trial_booked and inf_trial = date-time.
  • Reminders: day before + 2 hours before (Utility template if outside 24 h).
  • No-show → reschedule message next morning.

Plan match chatflow

  • Goal → time → budget → recommended plan (₹17,500 Diwali pass, Jodi ₹30,000, Parivaar ₹14,500 each).
  • End with "Book a free session" → Booking chatflow.
  • When someone joins, the desk sets inf_stage = st_member — this stops all sales messages.
The intake reads inf_stage to decide who never gets a pitch. Keeping it right in these two chatflows (and at the desk) is the one manual habit that matters.

10Webhooks

Settings → Webhooks
1
URL: https://<project>.vercel.app/api/es/webhook. Verify token: the value of ES_WEBHOOK_VERIFY_TOKEN.
2
Copy EasySocial's signing secret into ES_WEBHOOK_SECRET. Requests without a valid x-hub-signature-256 are rejected.
3
Events: lead_create, lead_update and incoming WhatsApp messages / statuses. Set FORWARD_WEBHOOK_URL to a Google Apps Script URL to log every event into the lead sheet (optional). Delivery failures show in Vercel logs as wa_status … failed.
